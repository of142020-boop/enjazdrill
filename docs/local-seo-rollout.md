# متابعة الاستهداف المحلي

## ما تم تجهيزه
- صفحات الخدمات الثلاث ودليل الأسعار وصفحة مناطق الخدمة وروابط داخلية بينها.
- خريطة آلية: https://enjazdrill.com/sitemap-index.xml
- أحداث contact_intent لنقر الاتصال وواتساب وإرسال نماذج واتساب إلى dataLayer محلية.
- الأحداث مؤشرات اهتمام فقط؛ لا تثبت إرسال رسالة أو إتمام اتصال. لا تتضمن حقول النماذج أو نصوص الرسائل.
- لا يوجد حاليًا Analytics يستقبل الأحداث أو لوحة تقارير. يلزم ربط النظام الفعلي قبل اعتبار القياس نشطًا.

## متطلبات الإكمال الخارجي
- المستودع: https://github.com/of142020-boop/enjazdrill
- يلزم تأكيد منصة النشر وإعداداتها. GitHub CLI غير مسجل الدخول في جلسة التنفيذ؛ لم يتم دفع أو نشر التعديلات.
- يلزم رابط ملف النشاط الحقيقي في Google Maps لمراجعته.
- وجود وسم تحقق Search Console في المصدر لا يثبت الوصول للحساب أو نجاح التحقق.
- بعد النشر: فحص URL للرئيسية والخدمات ومناطق الخدمة، وإرسال خريطة الموقع من الحساب المالك.

## جدول أول 90 يومًا
1. أسبوع 1–2: النشر والتحقق من الفهرسة وربط القياس وتسجيل خط الأساس.
2. أسبوع 3–4: توثيق أول مشروعين فعليين إذا توفرت الصور والمقاسات وإذن النشر.
3. الشهر الثاني: مراجعة استعلامات الخدمات والمناطق وتقييمات العملاء وتحديث الصفحات وفق النتائج.
4. الشهر الثالث: اختيار توسع جغرافي بناء على الطلبات المؤهلة والأعمال المنفذة.

## قالب توثيق مشروع
الخدمة، المنطقة دون عنوان العميل، المطلوب، المقاسات الفعلية، التجهيزات، صور مأذون بنشرها، نطاق التسليم، رابط الخدمة. لا تنشر حالة قبل اكتمال المعلومات.

## سجل الطلبات المقترح
تاريخ الاستفسار، الخدمة، المنطقة، المصدر (سؤال العميل عند الحاجة)، هل الطلب مؤهل، هل تمت معاينة، هل نُفذ العمل، قيمة العمل. افصل نقرات الأزرار عن العملاء المؤكدين.

## التحقق المحلي
npm run build
python scripts/check-seo.py

## تغطية المحافظات
أكد صاحب النشاط قبول أي حجم عمل في أي مكان بمصر. أضيف دليل المحافظات و27 صفحة مستقلة مع تفاصيل تنسيق الوصول وقوائم مدن ومراكز، وروابط للخدمات ورسائل طلب تحدد المحافظة. لا تُعرض فروع أو مشروعات غير موثقة.
بعد النشر تُراجع صفحات المحافظات في Search Console حسب الاستعلامات والطلبات المؤهلة. تُضاف حالات تنفيذ محلية فقط عند توفر بيانات وصور مأذون بنشرها. لا تُولد صفحات إضافية للقرى والمدن بمجرد استبدال الاسم.
أحداث contact_intent تحمل المحافظة في governorate على صفحات المحافظات؛ الربط بنظام تقارير ما زال مطلوبًا.

## تحرير محتوى المحافظات
أعيدت كتابة متن كل محافظة في src/data/governorate-editorial.ts: مقدمة وأربعة أقسام وقائمة تجهيز وسؤال وجواب مستقلة. أزيلت كتل شرح الخدمات والأسئلة العامة المتكررة من قالب المحافظة، مع إبقاء روابط الأدلة الفنية. الأوصاف تستمد من مقدمات الصفحات ويضاف رقم الهاتف دون تكرار.
السيناريوهات مشروطة أو تخطيطية وليست ادعاء تنفيذ مشروعات. لا توجد أرقام طلب أو أسعار أو فروع مختلقة. يظل دعم الصفحات بمعلومات العمل المحلي الفعلي والصور المأذون بها مطلوبًا عند توفرها.
فحص scripts/check-governorate-content.py يقارن تداخل مجموعات من خمس كلمات في المقالات الناتجة، ويستبعد رأس وتذييل الموقع. النتيجة مقياس تحريري للتكرار الحرفي فقط؛ ليست مقياس ترتيب أو ضمانًا لسياسات Google. تستمر مراجعة الطلبات والفهرسة بعد النشر.

## نطاق استهداف المحافظات
حسب توجيه صاحب النشاط، صفحات المحافظات تستهدف الكور وقص الخرسانة فقط. أزيلت منها أمثلة تركيب الشفاطات وروابطها ومقدماتها، مع الاحتفاظ بصفحة الشفاطات الأساسية والتنقل العام إليها.

## تحسين الصور
أضيفت صور الكور والمنشار الحالية إلى صفحات المحافظات بصفتها صورًا توضيحية للخدمة، لا أعمالًا محلية موثقة. مكون SiteImage يقرأ الأبعاد الفعلية من image-metadata.json ويقدم srcset. الأمر prepare-images.mjs يعمل قبل التطوير والبناء ليولّد نسخ WebP الأصغر دون تكبير الأصل. الفحص المحلي يتحقق من الأبعاد والنصوص البديلة ومصادر الصور المتجاوبة.
